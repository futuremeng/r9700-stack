Three things that bite when pasting: LiteLLM and the OpenAI SDK want the base
        ending in /v1, and the blocks below spell each full path once — putting the
        base in front of a path that already has it is how /v1/v1/chat/completions happens. The model
        string is openai/<served name>, and these launches run a reasoning parser —
        message.content can come back None with everything spent on
        message.reasoning_content, because reasoning counts against max_tokens. The
        path under "Weights live at" is where the checkpoint is, not a name a client can ask for — asking by it
        gets a 404 that lists the aliases this serve does accept. The base URL above is the address this
        browser reached the serve on, not what a sidecar dials internally, so it pastes correctly on the
        machine you are sitting at. On a box that runs a gateway in front, the address printed above belongs to
        the gateway: the same URL answers /v1/chat/completions, /v1/embeddings and
        /v1/rerank, and the process behind it binds loopback — the Configuration card names both.
        The API key is never printed here: if the serve has one, name it in the environment.

Alert everyone in the group
        

      

      
What this sends: the hardware claim the Monitor is showing — N driver page faults on
        one PCI function inside the window — with the two sentences the Monitor shows (what was counted, and the
        physical action) and the per-card fault shapes. It is sent by setup.py at the moment a rank dies,
        after the ledger line in .r9700-state/faults.jsonl is written and before any
        relaunch, so a machine that resets itself cannot later claim nothing happened.
        Three things that bite: the message always carries the keyword above, because the robot's security filter
        drops anything that does not and answers with a JSON errcode rather than an error; the webhook is a bearer
        credential for the group, so this page shows its host and path only, and the file is 0600;
        and Saved is not working — the Last send row above is the robot's own answer,
        recorded in .r9700-state/notify-last.json by whichever process sent it.
